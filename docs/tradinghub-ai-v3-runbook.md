# HCTradingHub AI Assistant: build 3 runbook

## What is connected

The assistant uses the existing authenticated TradingHub route, module toggle, user-scoped conversation tables, approved FAQ and Knowledge Base records, published Market Analyst outlooks, read-only Trading Journal context, and deterministic structure/risk/break-even calculators. Market Insight can supply saved REAL snapshots only through the existing permission and freshness checks. A snapshot is not a live quote. Gemini generation is optional and uses a server-side key and versioned system instruction.

There is **no verified live quote adapter, exchange order book, current news/calendar source, chart image ingestion, order execution, broker account change, or semantic embedding service** in this assistant. `live_data_enabled` and `chart_reading_enabled` remain false in build 3. The journal mode is an administrator switch for the already existing read-only, user-scoped context; it can be disabled. The application does not expose a distinct tenant identifier for these chat tables, so isolation is by authenticated user and TradingHub module.

Current question flow: authorize → validate → save the customer message with its idempotency UUID → select the published prompt version → use exact published FAQ or reliable article when possible → optionally use authorized historical/journal context and provider generation → reject unsupported live/citation claims → save answer attempt, sources, prompt version, model and status. A provider failure leaves the customer question in history. Regeneration uses a new answer attempt tied to the same question, with a separate UUID and a limit of four attempts. It never silently trains a third-party model on stored conversations.

## Knowledge and prompt operations

- **FAQ:** TradingHub → AI Assistant → AI Training. Create a draft, add approved answer and alternative wording, submit, approve, publish. Edits return a published FAQ to draft. Archive when obsolete. Only published, approved, effective content answers customers. The 45 seeded owner-specified answers cover 15 topics in English, Simplified Chinese and Bahasa Melayu. Rerunning the seeder does not overwrite administrator edits.
- **Articles:** Open AI Knowledge Base. New articles start as draft and pass submit → approve → publish. Record module, level, asset classes, source type, original URL if applicable, owner, verification and expiry dates. Legacy `active` articles remain available for compatibility; prioritize their revalidation, especially old platform or time-sensitive claims. Published articles past `effective_until` are excluded. The AI Training dashboard counts legacy/published articles lacking recent verification.
- **System prompt:** AI Training → System Prompt. Version 3 contains the owner-supplied master prompt in `database/seeders/data/trading_ai_master_prompt_v3.txt` and `ai_chat_prompts`. A new revision is immutable after saving and must move through draft → pending review → approved → published. Publication archives the prior version. Ordinary customers have no access. The selected version is sent using Gemini `systemInstruction` and recorded on messages. Fixed server access, risk and data freshness guards still run before generation.
- **Feedback:** Members rate the exact answer and may identify incorrect, outdated, unsafe, unclear or missing-data responses. Administrators review the answer and its prompt version on AI Settings, record a resolution, and create a new draft if needed. Historical answers are retained as delivered.
- **Unknown questions:** Review the redacted grouped queue, its frequency and failure reason. Draft and publish an answer after source verification; generated responses are not silently promoted to approved content.

Do not label editorial/owner-provided educational text as a verified live quote, official regulation or broker specification. For changing facts, cite the original source and set a review/expiry date. Human review is required before high-impact prompt and policy publication.

## Quality rubric and baseline

The fixture `tests/Fixtures/trading_ai_evaluations.php` contains 50 curated questions: 15 approved curriculum questions in each of English, Simplified Chinese and Bahasa Melayu, plus five unsupported or adversarial requests. `TradingAiQualityTest` checks exact approved-answer routing, language, version/source provenance, no provider call in knowledge-only mode, and safe abstention for live price, guaranteed signal, current news, chart image and instruction-extraction prompts. The baseline is 50/50 passing in the isolated test database; this is retrieval/guard coverage, **not a claim of perfect real-world accuracy**. Additional tests cover prompt publication, retry idempotency, feedback, article approval, expired content, malicious article text, fabricated URLs and decimal calculations.

Local verification on 26 October 2026: the focused AI quality suite passed 13 tests and 311 assertions; Blade templates cached successfully. The repository-wide suite finished with 405 passed, one skipped and one unrelated existing PMS failure: `ProjectManagementV2Test` expects `analytics.basis` to be `issue count`, while the current PMS endpoint returns `development-applicable tickets`. No PMS source was changed in build 3.

For human review, score each sampled answer 0–2 for factual accuracy, grounding, risk safety, numerical correctness, helpfulness, clarity, citation validity and appropriate abstention. Any fabricated live quote, cross-user disclosure, unsupported order instruction or incorrect monetary risk calculation blocks release. Record the question, locale, answer/source IDs, prompt version, expected result, reviewer and resolution. Repeat the fixture and sampled human review after prompt, curriculum or provider changes.

- On staging, back up the database, deploy code, apply both build 3 migrations if the earlier AI migrations already exist, and run `TradingAiMasterPromptSeeder` and `TradingAiCurriculumSeeder`. Verify the system prompt version, three language examples, FAQ publication, queue and feedback access, user/module isolation, duplicate/retry behavior, published outlook timestamp, and missing-data responses. Successful provider responses store provider-reported input/output token counts and model version when supplied; there is no cost estimate without verified pricing.
- Run PHP/unit/feature tests, Blade and JavaScript checks, and desktop/tablet/mobile keyboard and scrolling checks with an authenticated test account. A local desktop Chrome screenshot was checked; tablet/mobile and keyboard checks remain staging release gates.
- A qualified legal/compliance reviewer must approve any personalized regulated advisory feature and local advertising language before production launch. Build 3 does not add personalized order instructions or execute trades. A live provider request was not made during local tests; test production credentials, quota and provider responses in an authorized staging environment.

## Rollback

Disable the AI submodule, export custom prompt revisions, feedback, answer attempts and Knowledge Base provenance, and restore the pre-release code if needed. Roll back migrations `000002` and `000001` in that order only after those records and provider usage are backed up. `000001`'s `down()` stops if prompt revisions newer than version 3 or multiple answers per question exist; remove those additions in a reviewed rollback procedure rather than silently discarding them. Dropping `000001` removes the new prompt table and provenance/audit columns. Restore the saved database dump if a full local recovery is needed. Do not roll back the earlier AI migrations merely to revert build 3.
